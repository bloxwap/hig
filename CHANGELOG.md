# Changelog

## Unreleased

Fixes and gaps from the browser and native audits of the app conversions to the 0.7.0 blocks. These change rendering on purpose: the one-line `MarketRow`; switch rows named once on web; the `SwapPanelBlock` title drawn as the shared `ScreenHeader`; native setting rows matching web (the switch as its 48dp row, a described row 71 → 79dp); the `TradeHistoryListBlock` empty and error line without bottom padding; a live `AnimatedNumberReadout` drawing its reels in its own flow, so its box is as wide as what it draws (wider on Android); whole price presets dropping their fraction digits; native `PresetGroup` labels on one line that shrinks to fit, and its `label` moving from the container to each chip's hint; and a native block's pinned header filling its whole height once content scrolls under it. Everything else is additive and optional. Web and native unless noted.

- **Defect fix, rendering change: `MarketRow` in action mode is one line.** On web the stylesheet laid out the identity only in presentation mode and the row wrapped, so with an icon, a detail line and trailing content the avatar stacked above the name and the trailing content dropped to a second band (rows measured 126px, 178px for a long name, in the app's market picker). Now the identity (favourite, icon, then the name over its detail) holds the leading edge, the figures, trailing content and check sit on the trailing edge, nothing wraps, and the name and detail truncate with an ellipsis. When a row is too narrow for everything, space goes in a fixed order: the name truncates down to a floor (the name button keeps 5em, so the icon never leaves the identity and the start of the name stays readable); then whole figures drop from the end (volume, then change, then price), never cut mid-number; then the trailing content is clipped; the check always keeps its place. In an action row the figures sit in a new `span.hig-market-figures` (presentation mode keeps one grid column per figure). The name sits in a new `span.hig-market-label`, and the name button has no block padding and now fills the identity, so a row is 56px, 58px with a detail line: measured in Chromium and WebKit (playwright-core, against a fixture bundled from the built dist) at 310px, 402px and 600px, rows with an icon, a detail line, a price, a change, a volume, trailing content and `selected` are 58.02px with no overflow and no overlapping cells (at 310px such a row keeps the name's floor, the trailing content and the check and drops the figures; at 402px it also shows the price), and the plain row (name, price, change) is 56px with both figures. Native rows with host options had the same class of problem (`flexWrap: 'wrap'`, untruncated names, and an identity that could collapse under a fixed-width icon): they no longer wrap, the name and detail take `numberOfLines={1}`, the name cell has a 96dp floor and never shrinks, the figures drop from the end the same way and the trailing content clips last (checked with Yoga at 310/402/600dp), and the vertical padding is 8dp with an unpadded name button (60dp with a detail line). The native plain row is unchanged. Catalog state `one-line` gains a row with a price, a change, trailing content and `selected`.

- **Pinned headers on five more blocks, and no jump when they pin.** `stickyHeader` on `ProfileBlock` (its top bar), `ManagePositionBlock`, `AccountBlock`, `TokenActionBlock` and `LanguageBlock`, through the shared piece: web in the nearest scroller; native as the block's own scroll view, with `stickyHeaderBackground` and `scrollComponent` and test IDs `profile-sticky-header`, `manage-sticky-header`, `account-sticky-header`, `token-sticky-header` and `<testID>-sticky-header` (`language-sticky-header`). On web a header that leads its pane now pins where it rests instead of sliding up by the padding between it and the scroller first (the leaderboard header moved 12px): the script measures that padding into `--hig-sticky-inset` (marked `data-sticky-inset`), the fill reaches up to the scroller's edge through `--hig-sticky-cover`, and the fill appears on `data-scrolled` the moment it pins. Measured in Chromium and WebKit with a 12px scroller padding and a 16px pane padding, the `AccountBlock`, `ProfileBlock` and `RewardBlock` headers stay at 28px at every scroll offset. A header that follows other content in its pane pins at the edge, as before. Native block scroll views already pinned without moving.

- **New: `PresetGroup` (web `@bloxwap/hig/react/selection`, native `@bloxwap/hig/native/selection`).** Quick choices as chips in an equal-width grid that fills its container's width, for order sizes, leverage steps and the like: `options` of `{value, label, disabled?, testID?}` (string or number values), one selected `value` or none (`null`), `defaultValue`, `onValueChange`, `columns` (one row by default; fewer columns wrap the chips onto rows that keep the column width), `selectedIntent` (`primary` default), `disabled`, `label` (accessible name, not drawn), `testID` and `suppressFeedback`. Each chip is a HIG `Button` in the interface face: web a toggle button with `aria-pressed` in a `role="group"`, at least 44px tall at either density, an option's `testID` as `data-testid`; native a Button that reads `accessibilityState.selected`, 44dp with a 48dp touch target, an option's `testID` (or `<testID>-<value>`) as its test ID. A new choice plays the provider's `selection` feedback once the value lands, like `SegmentedControl`. `TargetBlock` now draws its presets with it, so there is one implementation; its presets render as before, except that a press on the already selected preset no longer reports it again, a new choice plays `selection` feedback instead of `activate`, and on web the chips keep 44px at compact density. `useControllable` (web and native) accepts `intent: null` to commit without feedback. Catalog entry `preset-group` with a `grid` state.

- **Defect fix (native, Android), rendering change: a live figure is as wide as what it draws, and no glyph is clipped.** Every digit reel takes the widest digit's advance, while the reading keeps the face's own digit advances wherever `tabular-nums` is not honoured (Android with HIG's faces), so the reels were wider than the readout's box. Drawn as a clipping overlay on the hidden reading, they lost the last digit of a left-anchored figure (`$1,000.0(`) and the leading symbol of a right-aligned one; and on the Seeker the trade detail drew `+100.00%on margin`, the box the width of the reading (59.7pt on both phones, the following words at x 197.7) while the reels drew over the space before ` on margin`. `AnimatedNumberReadout` now draws the reel row in its own flow, so the box is laid out from the parts it draws (the composed sign, every static part read from the text, each reel at the widest digit's advance, the affixes), and the reading leaves the flow while the reels show (it stays, invisible, for assistive technology and `testID`, on the side the figure is aligned to). Nothing is measured to size the box (no `onLayout`, no `minWidth`) and nothing clips but each reel's own column, so no frame cuts a glyph. Where the parts are wider than the reading (separate texts lose its kerning, a face without tabular digits) the box is wider by that much, so text after it moves over; where they match, as on iOS, nothing moves; the static fallbacks (reduced layouts, RTL, opaque text) keep the reading's width. Checked with Yoga 3.2 (an in-flow row sizes its box to the row; tests cover the structure, not device pixels).
- **Native touch targets, checked against the 48dp rule.** HIG's native rule is a 48dp touch target around a smaller visual, not a 48dp visual. `docs/foundations/platform.md` line 102 sets the comfortable "control/target 48" and says "Painted icons can be 16/20/24 while targets stay 48 on touch"; line 112 gives buttons, segmented controls and single-line text inputs "one height on web: 44 units on touch density". So `Button`, segments and chips keep their 44dp visual on Android as on iOS, the height web draws them at, and the 0.7.0 controls under 48dp reach a 48dp target through `hitSlop`. Android's Fabric renderer counts a child's `hitSlop` in its parent's overflow inset (`YogaLayoutableShadowNode`), so slop past a row's own frame is reachable there too, unless a clipping ancestor cuts it. Checked per control: `Button` 44 + 2 + 2 = 48 tall; `SegmentedControl` segments 36 + 6 + 6 = 48, vertical only, 4 apart. Two fixes: compact `SegmentedControl` segments (28dp) reached only 40dp and now take 10dp of slop each side (48); `PresetGroup` chips take 4dp of slop to each side as well as 2dp above and below, half the 8dp gap, so neighbouring targets meet but never overlap and a chip squeezed under 48dp wide (seven columns in 320dp) still takes its whole column pitch. No visual height changes.
- **Defect fix (native): a block's pinned header fills its whole height once content scrolls under it.** With `stickyHeader`, the blocks pin their header as their scroll view's first child, which carried the 16dp inset and the fill. React Native's sticky slot moves that child's style onto its own wrapper and gives the child `flex: 1`, which measured 0 tall on the iPhone simulator, so the scrolled fill covered only the 16dp inset and the header's content showed the rows through it. The pinned child now carries only a row direction for that wrapper (where `flex: 1` fills the width and the height follows the content) and the inset and fill sit on the inner view, so the header keeps its height in a `ScrollView`, `BottomSheetScrollView` or any scroller that honours `stickyHeaderIndices`. Applies to every block with native `stickyHeader` (they share `StickyHeaderLayout`); at rest nothing changes.
- **Defect fix (native): a pinned `ScreenHeader` fills its inset, with the new `inset`.** A host that pins `ScreenHeader stickyHeader` as its own scroller's first child (`stickyHeaderIndices={[0]}`) makes the header element itself React Native's sticky child, so React Native moves the header's `style` prop onto the slot's wrapper and passes `flex: 1` in its place. The row layout and the fill stayed on the header, but a host inset passed as `style` padding (the blocks' 16 above and to each side) landed on the wrapper, outside the fill, so once content scrolled under it the rows showed through a 16dp band above and beside the 44dp row (Yoga, 402dp wide: the filled row 370 × 44 inside a 60dp slot). With `stickyHeader` the header is now an outer view carrying only what may move (the host's `style`) and a minimum height of the whole row, around the row with the back control, the title and the action, the inset and the fill; new `inset?: number` puts that inset inside the fill (`inset={16}`: the filled row is 402 × 60 in the same slot, and stays 60dp tall whether or not `flex: 1` collapses it). Test IDs are unchanged (`<testID>-header` is the row). Pass the inset as `inset`, not `style` padding, to get the fill over it; a host `style` with `stickyHeader` now always sits outside the fill (before, it was inside the fill only when the scroller did not pin the header). Without `stickyHeader` the header is one view as before and `inset` is ignored.
- **Defect fix: the `TradeHistoryListBlock` empty line has no bottom padding of its own.** The empty line (and an `error` in its place) kept 32 units above and below it, so with the block's 16 inset the text sat 48 above the foot of a sheet (measured 50pt on device). It now keeps 32 above and none below, on web (a rule on `.hig-trade-history-list > .hig-swap-empty`; the shared picker empty line is unchanged) and native. Native: an empty or error state is 32dp shorter.

- **Rendering change (native): setting rows match web.** The settings blocks' separate cards stay 8 apart and a `SignalsBlock` group's 2 apart, as on web (`.hig-setting-cards`, `.hig-setting-list`), but the rows themselves differed: native drew the switch at 32dp in a card padded 12, so a row with a one-line description measured 71.7dp against web's 79, a plain row's label and track sat 4dp above centre, and the switch's touch target was 32dp tall. Native heights: a plain row 56dp (unchanged), a described row 71 → 79dp (each further description line still adds 21), a card with content under its switch 12dp taller (20dp with a description).

- **Defect fix (native, iOS), rendering change: signed figures keep their plus sign.** Hermes' `Intl.NumberFormat` on iOS ignores `signDisplay` and has no `formatToParts`, so on a physical iPhone 17 Pro every `exceptZero` / `always` figure lost its plus (`12.34%`, `$1.542`, `$12.50` where Android drew `+12.34%`, `+$1.542`, `+$12.50`: the trade detail and history results, the manage-position result, `TargetBlock` amounts, and anything else drawn through `AnimatedNumberReadout`, `Usd`, `Percent` or a block's own number text), and live readouts drew static text because the reel model needed `formatToParts`. Native HIG now composes the sign itself: it formats the magnitude and the locale's own negative form without `signDisplay` and puts a plus where the minus sign stands, so the sign keeps its place against the currency sign, percent sign, digits and bidi marks (`+$12.50`, `+12,50 $US`, `$+12.50` in de-CH, `؜+١٢` in Arabic, U+2212 locales such as Swedish). Zero follows the rounded figure (`exceptZero` draws `0.00%` for 0, −0 and 0.00001), and `always`, `never` and `negative` are composed too. The reels read their parts from that text when `formatToParts` is missing or does not spell it: digits before the locale's decimal separator are integer places, after it fraction places, with the same keys Intl's parts give, so iOS rolls the same reels as Android (scientific notation, RTL layouts and bidi marks stay static as before). New contracts exports `formatSignedNumber`, `intlSignDisplaySupported` and type `SignDisplay`; contracts `formatNumber` uses `formatSignedNumber` only where the runtime fails `intlSignDisplaySupported`, so web, Android and any Intl that honours `signDisplay` format exactly as before (one `Intl.NumberFormat` with the caller's options). `tests/native/sign-display.test.cjs` stubs an Intl with neither feature for currency, percent, plain numbers, zero, negatives, the reel model and the blocks, and checks the composed string against Node's ICU in 46 locales × 14 formats × 5 sign modes × 10 values (32,200 strings, none different).

Native `PresetGroup` labels are one line that shrinks to fit the column (`numberOfLines={1}`, `adjustsFontSizeToFit`, down to 75%) instead of wrapping; each chip keeps Button's label colours and is named by its label, and a label takes the test ID `<chip testID>-label`.
- **`AssetsBlock` joins the round-three conventions (web and native).** The name and the symbol line of a row are one line each and truncate (web `.hig-assets-text > *` with an ellipsis, native `numberOfLines={1}`), as `MarketRow` rows are. New `headingId` names the heading (web `id`, native `nativeID`) and new `stickyHeader` pins the header: web through `ScreenHeader stickyHeader`; native as the block's own scroll view through the shared sticky layout, with `stickyHeaderBackground` and `scrollComponent`, test ID `<testID>-sticky-header` (`assets-sticky-header`).
- **`AssetsBlock` trailing content and a clearable search (web and native).** An asset's new optional `trailing` draws host content on the row's trailing edge before the signal disc (web `.hig-assets-trailing`, native test ID `<testID>-<id>-trailing`), such as the live result of an open position, which the app's market picker drew before it moved to the block. The new `clearable` shows `SearchInput`'s clear button while the field holds text (`messages.clearSearch`, native test ID `<testID>-search-clear`); it empties the query and returns focus to the field. Rows and fields without them are unchanged. The one new rule takes the docs CSS to 184,099 bytes, within its 185,000 budget.

Rules with identical declarations now share one selector list (the blocks' 16px column, the 8px and 12px stacks, the row, avatar and image rules LanguageBlock, AssetsBlock, the asset and trade rows share, the bar tracks, the sticky header and profile bar, the checks), and the three signal tints read one custom property: the docs CSS is 183,982 bytes. - **Preview: HIG's own native sheet (`@bloxwap/hig/native/gesture-sheet-next`).** `GestureSheet`, `GestureSheetHost` and `GestureSheetScrollView` built on Reanimated and Gesture Handler, with no sheet library, written to replace the `@gorhom/bottom-sheet` backend that stutters on Android. Fixed detents or content sizing, modal (in `GestureSheetHost`) or inline, scroll handoff, rejected dismissals, Android Back, reduced motion and the iOS keyboard are covered. Not yet measured on devices, so `@bloxwap/hig/native/gesture-sheet` is unchanged. See Overlays, Native sheet engine.
- **New: `GestureSheetView` (web `@bloxwap/hig/react/gesture-sheet`).** One view of a sheet that shows several, such as the steps of a flow. When `viewKey` changes, the old view fades and shrinks out of the way without holding its space, the new one fades in at its own size, and a content-sized sheet moves to the new height at the same time, all on one curve with no overshoot (`cubic-bezier(.26,.08,.25,1)`; 270ms out and for the height, 220ms in), the values of Vaul's Dynamic Drawer. The web sheet's content-size animation moves from 200ms to these values. Going deeper and going back look the same. A leaving view never makes the sheet scrollable. Nothing moves under reduced motion. The GestureSheet docs demo is now an order flow three levels deep.
- **Rendering change: bar fills draw at half strength.** The segments of `BarMark`, the entry-to-mark stretch of `BarPnl` and the entry-to-trigger stretch of `TargetBlock` are filled at 50% of their colour, so a wide bar no longer outweighs the figures beside it. The edge ticks of a stretch, the liquidation tick, the legend dots and the price readouts stay solid. Web sets the strength with `--hig-bar-fill-opacity` (default `.5`; `1` restores the solid fill); native exports `barFillOpacity` from `@bloxwap/hig/native/bar-mark`, and the `BarPnl` and `TargetBlock` fills are their own views with the test IDs `<testID>-fill` and `target-fill`.
- **New: `NumberFlow` (web and native `animated-number` entries).** `AnimatedNumberReadout` under the name the product uses, with NumberFlow's motion as its default; `motion="flow"` gives the same to `AnimatedNumberReadout`, which still slides unless told otherwise. Flowing, every changed digit rolls through the digits between its old and new value, a new value joins the motion in flight instead of restarting it, and timing is NumberFlow's (900 ms on its settle, 450 ms fades). New props on both platforms, with the reference's names: `animated`, `spinTiming`, `transformTiming`, `opacityTiming`, `digits` (`{1:{max:5}}` wraps the tens of a seconds counter at 5), `continuous` and `willChange`; web adds `className`. On web a figure that gains or loses a place slides closed while the place fades, clipped at its moving edge, and `NumberFlowGroup` slides neighbouring figures with it; everything is additive Web Animations started in the commit that draws the value, and a browser without them draws each value at once. On native a place mounts its reel the first time it turns (one glyph at rest instead of twenty) and rolls on the UI thread; the figure's width still changes at once. On both, a new locale or format is drawn at once rather than rolled to. The shared arithmetic is `@bloxwap/hig/contracts/number-flow`. Existing `AnimatedNumberReadout` props and motion are unchanged. See Financial data, NumberFlow, which maps the product's `@number-flow/react` and native `Flow*` props to these.
- **New: one toast API on web and native (`@bloxwap/hig/react/toast`, `@bloxwap/hig/native/toast`).** `Toaster` mounted once, then `toast(message, options)` and `dismissToast(id?)` from anywhere, with the same options on both platforms: `severity`, `description`, `action`, `duration`, `id` to replace a notice in place, `dismissName`, `onDismiss` and `onAutoClose`. `toast.success`, `toast.error`, `toast.warning` and `toast.info` set the severity, and `toast.dismiss` is `dismissToast`. It has not run on a device. Web keeps Sonner as the engine and gains `description`, the severity shorthands, `onDismiss` and `onAutoClose`; the close button's name now comes from the provider's translation without the caller passing it, Sonner's region takes `messages.notifications`, and a provider that asks for reduced motion stops Sonner's transitions. **Rendering change on web:** a numeric `offset` or `mobileOffset` (and the defaults, 24px and 16px) is now added to the safe-area inset of each edge, so toasts clear a notch or home indicator; on a screen without insets nothing moves. `offset` also places the stack on windows under 600px now, as it does on native, unless Sonner's `mobileOffset` is given. On both platforms `left` and `right` are the physical sides in either direction, a `duration` that is not a positive number takes the Toaster's, and one longer than a timer can count keeps the notice. The figures both hosts share are exported from `@bloxwap/hig/contracts/toast`. Native `status` exports the capsule as `ToastNotice`, as web does, and web `ToastNotice` takes `description`. See Status & feedback, Transient toasts.

Recipes are now called blocks, and this release adds the screens the apps are built from: `AccountBlock`, `TokenActionBlock`, `ManagePositionBlock`, `PositionBlock`, `TargetBlock`, `TradeHistoryListBlock`, `TradeHistoryDetailBlock`, `ProfileBlock`, `RewardBlock`, `LanguageBlock`, `SoundHapticsBlock`, `SignalsBlock` and `NotificationsBlock`, beside `SwapPanelBlock`, `FromPickerBlock` and `ToPickerBlock`. New components `BarMark`, `BarPnl`, `AssetBalanceRow`, `ListGroup` and `ListRow` carry them.

Upgrading from 0.5.x:

- Removed with no replacement in HIG: `ActivityList`, `BalanceCard` and `CodeWindow` (and their `recipes/<name>` import paths, the `noActivity` message key and the `.hig-balance-card` styles), and `AmountInput` from the `field` entries. Draw these in the host, or use `Input` with a decimal keyboard in place of `AmountInput`. They were removed without the usual deprecation window, which is why this is a minor release with breaking changes.
- Renamed, with the old names still working as deprecated aliases until the next major release: `recipes` import paths are now `blocks`; `SwapPanel` is `SwapPanelBlock`; `FromPicker` and `ToPicker` are `FromPickerBlock` and `ToPickerBlock`. Move imports when convenient.
- Nothing else that shipped in 0.5.2 changed name or stopped resolving.

- New block `ProfileBlock` (`@bloxwap/hig/react/blocks/profile-block`, `@bloxwap/hig/native/profile-block`, and the `blocks` aggregates): a person's profile as one screen. A top bar with the address control and Close, the avatar (artwork, an address colour or initials) with an optional status dot, the name with an optional edit control, then sections of rows that open something, show a value or hold a switch. New message key `editName`.
- Docs: the Blocks section lists only blocks. `MarketRow` moves to Financial data, `TradeEntry` to Fields & inputs, and `InstallCommand` and `MarketingHero` to Actions & surfaces, with their documentation. Import paths are unchanged: all four still come from the blocks entry.
- `FromPicker` and `ToPicker` are renamed `FromPickerBlock` and `ToPickerBlock` (web and native), with `FromPickerBlockProps` and `ToPickerBlockProps`, like the other blocks. The old names keep working as deprecated aliases until the next major release. The import paths `@bloxwap/hig/react/blocks/pickers` and `@bloxwap/hig/native/pickers` are unchanged.
- Switch alignment (web and native). A switch in a row sits flush with the trailing edge and level with the first line of its label. On web the setting rows of `SoundHapticsBlock`, `SignalsBlock` and `NotificationsBlock` no longer leave a 4px gap after the track or centre it against a wrapped description, and a `ListRow` that holds a switch aligns its label, value and switch to the first line. Native `ListRow` aligns the same way; the native setting rows already did.
- New blocks `SoundHapticsBlock`, `SignalsBlock` and `NotificationsBlock` (`@bloxwap/hig/react/blocks/sound-haptics-block`, `blocks/signals-block`, `blocks/notifications-block`, the matching `@bloxwap/hig/native/<name>` entries, and the `blocks` aggregates): three settings screens built from one switch row, with the label over an optional description and the whole row as the target. `SoundHapticsBlock` draws one card per channel (`sections`), and a channel that is on can show its `source` device, a live `level` meter and its `volume` as fixed steps. `SignalsBlock` draws `groups` with a heading, an optional verified mark and small help pill, and switches sharing one container. `NotificationsBlock` draws one card per kind with an `error` line under it. Every word is host text.
- `SwapPanel` is renamed `SwapPanelBlock` (web and native), with `SwapPanelBlockProps` and the import path `@bloxwap/hig/react/blocks/swap-panel-block`. `SwapPanel`, `SwapPanelProps` and the paths `@bloxwap/hig/react/blocks/swap-panel` and `@bloxwap/hig/react/recipes/swap-panel` keep working as deprecated aliases until the next major release. `SwapSheet`, `SwapAmountCard` and the other swap pieces keep their names.
- New block `RewardBlock` (`@bloxwap/hig/react/blocks/reward-block`, `@bloxwap/hig/native/reward-block`, and the `blocks` aggregates): the screen for a trading competition. An optional promotion card (`promo`: a muted eyebrow, a rules text link, one large figure with a `caption` line under it, a headline and description read as one paragraph, and an action) that is a prize pool with a thin progress bar when it has a `goal` and a sweepstakes when it does not; an optional `tabs` choice of standings; the viewer's own standing (`you`) pinned on a tinted row; and the ranked `entries` with avatar, verified mark, a detail line and a score. Every word is host text. `rewardProgress` exposes the share of the goal. It was called `LeaderboardBlock` before its first release; the name, its types (`RewardBlockProps`, `RewardPromo`, `RewardEntry`), `rewardProgress` and the import paths now say Reward. Its headline figure is the same size as the `SwapPanelBlock` amount.
- New block `PositionBlock` (`@bloxwap/hig/react/blocks/position-block`, `@bloxwap/hig/native/position-block`, and the `blocks` aggregates): the sheet for the position being opened or edited. A header with Close, a summary of label and value lines (`details`, each a host string or a live figure, with an optional `positive`, `negative` or `muted` tone), an optional `note`, an optional paper trading switch (`paperTrade`) as a row of its own, and the settings as `groups` of `ListGroup` rows that open the host's views. Every label is host text.
- New block `LanguageBlock` (`@bloxwap/hig/react/blocks/language-block`, `@bloxwap/hig/native/language-block`, and the `blocks` aggregates): choose the app's language. A header with Back and the title, a search field that filters by name, description and code, then each language as a row with round flag artwork, its own name over the reader's name for it, and a check on the one in use. New message keys `language` and `searchLanguages`.
- New block `TargetBlock` (`@bloxwap/hig/react/blocks/target-block`, `@bloxwap/hig/native/target-block`, and the `blocks` aggregates): set a take profit or a stop loss on one position. `kind` is `take-profit` (positive role) or `stop-loss` (negative role). Under the shared header it shows the target as the headline figure in the chosen unit (dollars, price or percent), a price card titled with the position and the order type whose bar runs from the entry price to the trigger price, filled solid in the role colour, an optional note, the unit as a `SegmentedControl`, a Custom row, the host's quick choices as capsules, and Cancel beside the confirming action. Every trading word comes from the host through `labels`. `targetLayout` exposes the bar positions and `targetFormat` the number format of each unit. The prices sit directly on the screen; `surface` draws them inside a card. With `labels.info`, `note` opens in a popover from an info button on the trailing edge of the header. The bar has two points, entry and the trigger; the mark price, its `mark` prop and `labels.mark` are removed.
- New component `BarPnl` (`@bloxwap/hig/react/bar-pnl`, `@bloxwap/hig/native/bar-pnl`): a position's profit or loss as one bar. The stretch between entry and mark is filled solid `positive` in profit and `negative` at a loss, a tick marks each price, and the liquidation, mark and entry prices read under the bar in price order, so mark and entry trade places as the mark crosses the entry. `labels` is host text for the three prices; `side`, `title`, `description` and `priceOptions` are optional, `compact` shortens the prices for narrow screens, and `surface={false}` draws it without a card. `barPnlLayout` exposes the positions, order and result.
- New components `ListGroup` and `ListRow` (`@bloxwap/hig/react/list-group`, `@bloxwap/hig/native/list-group`), in Navigation: a grouped list for menus and settings. A group has an optional `title` and one rounded container; a row has a `label`, an optional `value`, `leading` and `trailing` content, and with `onSelect` (or `href` on web) becomes one target with a disclosure chevron.
- Breaking: the blocks `BalanceCard`, `CodeWindow` and `ActivityList` are removed (web and native), with their entries `@bloxwap/hig/react/blocks/<name>`, the deprecated `@bloxwap/hig/react/recipes/<name>` aliases, their catalog pages and examples, and the `noActivity` message key. Use `AccountBlock` for balances; for code, a `Surface` around `<pre className='hig-code'>` on web; for activity, `List` with its `empty` text.
- SwapPanelBlock `note` with `noteTone='warning'` or `'negative'` tints at 10% instead of 14% (web and native), the same as Alert. On a surface or sheet the negative note was 4.44:1 against its own tint; it is now above the 4.5:1 text minimum on the page, a surface and an overlay.
- Recipes are now called blocks. The docs chapter, the catalog family and the import paths use the new name: `@bloxwap/hig/react/blocks`, `@bloxwap/hig/react/blocks/<name>` and `@bloxwap/hig/native/blocks`. The published `recipes` paths (`@bloxwap/hig/react/recipes`, `@bloxwap/hig/react/recipes/<name>`, `@bloxwap/hig/native/recipes`) resolve to the same modules and are deprecated; move imports to `blocks`. They are removed in the next major release. Guide links to `components/recipes` anchors are recorded as renamed to `components/blocks`.
- `ManagePositionBlock`: on web the leverage in the position row takes the arrow's colour (green for long, pink for short), as it already did on native.
- `BarPnl` fills the stretch between entry and mark solid in the result colour (green in profit, pink at a loss), where it was a 24% tint.
- `BarPnl` gains `fit`, which scales the bar to the prices themselves so the move from entry to mark fills it; `barPnlLayout` takes the same option.
- New blocks `TradeHistoryListBlock` and `TradeHistoryDetailBlock` (`@bloxwap/hig/react/blocks/trade-history-list-block`, `@bloxwap/hig/react/blocks/trade-history-detail-block`, `@bloxwap/hig/native/trade-history-list-block`, `@bloxwap/hig/native/trade-history-detail-block`, and the `blocks` aggregates). The list is a history of closed trades as one screen: a header, then one capsule row per trade with round artwork, the asset's name over an arrow and the leverage in the direction colour, and the net result in the result colour over its age; `onSelect` makes each row a button with a disclosure chevron. The detail card shows the asset, the net result as the headline figure with the return on margin, the trade's figures as rows, and the host's actions in one row. Every label comes from the host. `TradeHistoryDetailBlock` draws nothing above its actions as a card: the asset, side and leverage sit on one line over the figure, `entry` and `exit` draw one bar with the two prices in place of two rows, and the remaining `details` form a three-column grid of small labels over values. `labels.netPnl` names the figure for assistive technology and is no longer drawn.
- New block `ManagePositionBlock` (`@bloxwap/hig/react/blocks/manage-position-block`, `@bloxwap/hig/native/manage-position-block`, and the `blocks` aggregates): the screen for one open position. A `BarMark` titled with the margin mode shows margin against notional and reads the share left before liquidation; a `BarPnl` places the liquidation, mark and entry prices. Both are drawn without a card because they are read-only. Under them, the host's actions as rows with chevrons and the position row with its profit and loss. Every label comes from the host through `labels`, because built-in strings carry no trading terms. `positionCorridor` exposes the share left before liquidation. The actions are one `ListGroup` of rows that share a rounded container.
- `BarMark` gains `surface={false}`, which draws no card around the bar, matching `BarPnl`. `TargetBlock` takes the same `surface` setting for its prices, off by default.
- New block `TokenActionBlock` (`@bloxwap/hig/react/blocks/token-action-block`, `@bloxwap/hig/native/token-action-block`, and the `blocks` aggregates): the screen for one token. A header with Back and the ticker, an assets `BarMark` (the token name, the total in dollars, and where it is held), a chains `BarMark` with the number of chains that hold a balance, then the actions as equal full-width buttons. `send`, `receive`, `stake` and `unstake` have built-in labels; other actions bring their own. New message keys `receive`, `stake` and `unstake`. `BarMark` gains `size='small'`. Both bars are drawn without a card.
- New block `AccountBlock` (`@bloxwap/hig/react/blocks/account-block`, `@bloxwap/hig/native/account-block`, and the `blocks` aggregates) and new component `AssetBalanceRow` (`@bloxwap/hig/react/asset-balance-row`, `@bloxwap/hig/native/asset-balance-row`). The card shows a header (Back, centred title, optional trailing action), the total on the leading edge with a Deposit action on the trailing edge, the pinned dollar balance (`pinnedSymbol`, default `USDC`, always first and always shown, $0.00 when not held), then every other holding by dollar value, largest first. Each holding is an `AssetBalanceRow`: artwork, name over symbol, value over units, in a capsule row 8 apart. All figures update place by place. `onShowAddress` adds a QR button on the trailing edge of the header, above Deposit; the host shows the account address. New message keys `account`, `deposit`, `accountBalance` and `showAddress`.
- New component `BarMark` (`@bloxwap/hig/react/bar-mark`, `@bloxwap/hig/native/bar-mark`): a one-dimensional stacked bar for parts of a whole. A card with a `title`, a `description` on the trailing edge, one rounded bar divided among its `elements` (`{label, value, tone, color, detail}`), and a legend of colour dots and labels. `total` leaves the remainder as empty track. Elements take the `positive`, `info`, `warning`, `negative`, `muted` and `faint` roles in order unless they name a `tone` or a host `color`. The layout follows the writing direction, and each legend item reads its share as a percent.
- Breaking: `AmountInput` is removed from `@bloxwap/hig/react/field` and `@bloxwap/hig/native/field`, with its catalog page and examples. Use `Input` with `type='text' inputMode='decimal'` on web or `keyboardType='decimal-pad'` on native; the rendered input is the same. `TradeEntry` does this itself and is unchanged.

## 0.5.2

SwapPanel takes the last host rules that kept apps on their own amount sheets (web and native).

- `actionDisabled` holds the action for a host reason and `actionStatus` names it; the panel's own prompts (a token, an amount, the balance) still come first. `actionIntent='destructive'` draws the action as destructive.
- `SwapToken.decimals` caps the decimal places typed in token units. `limitToBalance` refuses a key that would pass the From balance.
- `SwapToken.icon`, `SwapToken.chainIcon` and `SwapDestination.icon` take an image URL or a host element (`SwapArtwork`).
- `banner` renders above the From card and `footer` under the action.
- Native: `SwapKeypad` and `SwapCapsule` are exported from `@bloxwap/hig/native/recipes`, as the web recipe already exports its keypad and pill.
- Swap card live numbers (web and native). New requirement in the recipes chapter: every number in the swap card that can change while it is on screen updates through `AnimatedNumberReadout`, moving only the changed places. `SwapPanel` now does this for the From balance, the fee and slippage on the To card, the settings rows and fee breakdown, and the picker balances (`FromPicker`, `ToPicker`), as it already did for the amounts and the conversion capsule. Hosts can pass live figures for their own text: `SwapDetail.value` accepts a number with `options`, `prefix` and `suffix`, and `SwapToken.caption` and `SwapDestination.detail` accept a `SwapFigure` (`{value, options, prefix, suffix}`). Strings still work and stay static. Web exports `SwapNumber` from the swap panel entry for host-drawn parts. Loading and unknown fees stay plain `…` and `—`; reduced motion updates without movement. Native: the conversion capsule now animates too, and `@bloxwap/hig/native/pickers` imports the animated readout, so it needs the optional Reanimated and Worklets peers as the swap panel already did.

## 0.5.0

Design review pass over all 65 catalog components (web and native). HIG now separates layers with fill and space, not strokes.

- Alert and Callout lose the glowing stroke (web and native): severity now tints the fill (the surface mixed with 12% of the tone) and colours the title, at the Surface radius with no border or shadow. `default` is a 6% `text` tint with the title in `text`. Hosts that restyled the 2px border or glow can delete those overrides.
- Tabs no longer use the action colour (web and native): the selected tab is a raised neutral capsule (`--hig-fill-raised`, `useFills().raised`) with `text`, and unselected tabs are bare `muted` labels, matching Navigation and SegmentedControl. Web selects them by `.hig-tab` instead of `[role='tab']`.
- Web: a comfortable density scope nested inside a compact one (a nested `HIGProvider density='comfortable'`, or `data-hig-density='comfortable'` on a wrapper) now restores the 44/48px control sizes and 12px gap; it used to stay compact.
- Visual balance pass (web and native). Thin tracks and rules follow the container like wells do: the Switch off track, Slider and Progress tracks, Spinner ring, Skeleton and Separator take the raised fill (`--hig-fill-raised`, `useFills().raised`), which is `nested` on the page and `border` inside a Surface, Dialog or sheet. On the page they were `border`, the lightest grey, and now sit level with a secondary button; Progress inside a card steps up from `nested` so it no longer matches an input. The platform guide states the rule.
- Disabled Button and IconButton are neutral instead of a half-opacity accent: a well fill with `muted` text for every intent, and no fill with `faint` text for ghost. Busy keeps the intent colour at 70% opacity under its spinner. The SwapPanel action row drops its own disabled override for the shared rule.
- Web: the Menu highlight and press step lighter (`border`) like Select options, instead of darker. Checkbox, Radio and Switch start on the content edge (no 8px leading inset; 16px trailing keeps neighbours apart) and group legends lose the browser's 2px inset. MarketRow in action mode draws the name in `text` and insets its trailing edge 20px to match the name.
- No resting strokes. Surface, Card, inputs, Select, Dialog, Sheet, Menu, Popover, Table and EmptyState lose their border. Control wells (inputs, segmented track, Badge, Avatar) take `surface` on the page and step to `nested` inside a surface or overlay; focus and invalid states keep a ring. Web keeps a transparent 1px border in the box, so sizes are unchanged and forced-colors still draws an edge.
- New colour role `overlay` (`#111111`, `--hig-overlay`): Dialog, AlertDialog, Sheet and GestureSheet panels use it, darker than a card, with a deeper shadow.
- Sheet handle: the GestureSheet drag handle is the action colour, so it follows `primaryColor`. Web draws it 100 × 6px with a soft glow in the same colour; native paints the indicator in `action`. Hosts can delete their own green handle styles.
- Form spacing rule in the platform guide: controls sit 8 apart in both directions, the bottom action row sits 16 below the content above it, and list rows that lead with an avatar are concentric capsules 8 apart.
- Web text fields are 44px high on touch density (36 compact), the same as buttons, down from 48. SearchInput text starts 42px in, down from 46.
- Button and IconButton: busy shows a leading spinner (in place of the icon on IconButton). The busy text is no longer drawn; it stays in the accessible name.
- SegmentedControl is inverted (dark track, lighter selected segment) and 44px high on touch density, 36px compact. Switch: the off track is dark grey.
- SearchInput and Search inset a magnifying glass on the leading edge. Web wraps the input in `span.hig-search-input`; the ref, class and props still reach the input. `SearchInput` defaults to `type="search"` and a host-supplied `type` now wins, so a host can keep a plain text field (no Safari search chrome) inside the HIG anatomy.
- Toast notices are single-row capsules: severity symbol, message, optional action, close symbol. The Dismiss wording moves to the close button's accessible name. Web markup changes from Alert sections to `.hig-toast-item`.
- New web entry `@bloxwap/hig/react/toast` (`Toaster`, `toast()`, `dismissToast()`) raises the capsule through Sonner; `sonner ^2.0.0` is a new optional peer. While a `Toaster` is mounted, `InstallCommand` reports its copy result as a toast; without one it shows the result inline as before. Only the toast entry loads Sonner.
- EmptyState is a centred stack under a default symbol. Web gains `illustration` (as on native) and `description` becomes optional.
- Accordion: outline chevron on the trailing edge that turns as the panel opens; the panel height eases where the browser can interpolate to `auto`. The whole header row is the target.
- Skeleton pulses, and StatusIndicator emits a ring in its status colour for `online` and `stale`. Both stop under reduced motion. Skeleton now fills its container width.
- Separator is a 2px line with rounded ends. Table separates sections with space and type weight instead of rules.
- Native: `useFills()` and `Raised` from `@bloxwap/hig/native/provider` expose the same page/raised fills for host-drawn controls; Button, IconButton and Tabs are 44dp with hit slop keeping a 48dp target; icons are drawn from plain Views, so `react-native-svg` stays optional. `InstallCommand` shows its copy result as a transient toast capsule (4s).
- New recipe `SwapPanel` (`@bloxwap/hig/react/recipes/swap-panel`, also in the `recipes` aggregates on web and native): send, swap and bridge in one panel, modelled on the swap product. From and To cards with a flip control, an amount in dollars or token units with a conversion capsule, token pickers (search, chain filter, Hot section) and settings (denomination, slippage, fee breakdown) pushed as views inside the panel, an on-screen keypad, a receive view, a `oneWay` mode that shows a down arrow instead of the flip control, and `denominationSwitch={false}` to fix amounts to one denomination and hide the conversion capsule. For flows beyond token-to-token it takes a fixed `destination` (a compact To card for a recipient wallet, staking pool or account), `lockFrom` / `lockTo`, and an `actionLabel`; a mounted `amount` seeds the entry. It also presents a token with a `caption` as an account, keeps the action disabled while `destination.pending`, shows `details` rows on the bottom card, and takes a `note`, a `title` with `onBack`, `controls={false}` and an `actionIcon`. The catalog example has one canonical state per flow: swap, bridge, send, deposit, withdraw, withdraw to another chain, stake, unstake. Catalog examples may carry per-state `variants`. `SwapSheet` (`@bloxwap/hig/react/recipes/swap-sheet`, `@bloxwap/hig/native/swap-sheet`) presents it in a gesture sheet, with the views pushing inside that one sheet. Fully host-driven: the host supplies tokens, balances, prices, the quote and the wallet, and executes on `onSubmit(action)`. Adds 43 `swap*` message keys. The docs stylesheet budget rises from 125,000 to 150,000 bytes for the new component styles.
- `SwapAmountCard` (web, from `@bloxwap/hig/react/recipes/swap-panel`): the swap From card on its own, for a host that enters a single amount such as a position size. `SwapPill` and `SwapKeypad` are exported from the same entry.
- New recipes `FromPicker` and `ToPicker` (`@bloxwap/hig/react/recipes/pickers`, `@bloxwap/hig/native/pickers`, and the `recipes` aggregates): the swap panel's source and destination pickers on their own. `ToPicker` is a destination address field with a scan button, alone or above a searchable token list with or without the chain filter. `FromPicker` shows a connected wallet with an optional disconnect button, or Connect wallet and a Generate address switch, above the tokens a wallet holds or a whitelist. `SwapPanel` uses both for its pushed views; its generate-address control is now that switch and no longer leaves the picker. `swapReceiveToAddress` is renamed `swapGenerateAddress`, and the token search now reads “Search name or paste address”.
- New `Filter` in the selection entries (web and native): one row of filter capsules that scrolls sideways, single choice, with a check that draws into the chosen capsule's circle. The swap token picker uses it for chains.
- Floating lists (Select, Menu, Popover, Tooltip) present with a short fade and settle. The Switch track eases with the thumb; both stop under reduced motion, like every other transition. The native Switch on web draws the HIG capsule instead of react-native-web's Material switch. The native Switch bundle budget rises from 2,200 to 2,400 bytes gzipped for it.
- New `VerticalAddress` (data entries) and `WalletAddress` (`@bloxwap/hig/react/wallet-address`, `@bloxwap/hig/native/wallet-address`) for Ethereum-style and Solana addresses: a Cuer QR code beside the address in fixed-width rows with the leading row and last four characters emphasised, and a Tap to copy hint when the host passes `onCopy`. `cuer` is a new optional peer. The SwapPanel receive view uses `VerticalAddress`; its two address message keys are now the shared `copyAddress` and `addressCopied`, with new `tapToCopy` and `qrCode`.
- Side-by-side actions are 8 units apart at every density through a new `--hig-action-gap` variable: Tabs and Pagination move from 12 to 8 on touch density; Alert actions, Filter and the SwapPanel rows already were.
- Closing call-to-action buttons sit a double step, 16 units, below the form and 8 from each other (`--hig-action-offset`, `.hig-form-action`): TradeEntry, the SwapPanel action row, and the buttons that end a Dialog or default sheet.
- The brand mark's copied-palette drift exception, expired on 2026-11-13, is renewed to 2027-05-12 and tracked in #201, so `npm run check` passes again.
- Examples: the IconButton example passes `busy`, and the Tooltip example confirms its copy with a toast.
- Accept the latest feedback and chart packages: the optional peers are now `@bloxwap/sfx` `^0.2.0 || ^0.3.0` and `@bloxwap/haptic` `^0.2.0 || ^0.3.0 || ^0.4.0`, and the required peer is `@bloxwap/chart` `^0.3.0 || ^0.4.0 || ^0.5.0`. HIG develops, smoke-tests and documents against chart 0.5.0, haptic 0.4.0 and sfx 0.3.0; PR CI still checks the oldest accepted versions. Native cues are re-exported with sfx 0.3.0 and are byte-identical.

## 0.3.0

- Every JS export now has a `default` condition beside `import`. Jest/jest-expo, `require()` and Metro's CommonJS resolution can import HIG entries instead of failing with `ERR_PACKAGE_PATH_NOT_EXPORTED`.
- `@bloxwap/hig/react/css` is touch-safe. Every `:hover` rule now sits behind `(hover: hover) and (pointer: fine)`, so taps no longer leave buttons dimmed or ghost buttons filled. Hosts can delete their sticky-hover overrides, and `tests/touch-css.test.ts` keeps the gate in place. HIG controls also get no tap highlight, `touch-action: manipulation`, no long-press selection, `:active` press feedback, 16px text fields on touch, overscroll containment, and safe-area padding on edge sheets and dialogs.
- Native market-direction colours: `useColors()` adds `up` and `down` (defaulting to `buy`/`sell`), `HIGProvider marketColors` overrides them and is inherited, and `NumberReadout`, `Usd`, `Percent` and `AnimatedNumberReadout` accept `tone="up" | "down"`. New types: `HIGMarketColors`, `HIGMarketColorRole` and `HIGTableColorRole`. `colorTable()` and `useBrandColors()` now return the table roles only. This replaces the mobile app's local patch of 0.2.0.
- Native `AnimatedNumberReadout` hides its underlying reading with clear white (`#ffffff00`) instead of `transparent`. Android Fabric reads `0x00000000` as unset and drew that reading in black under the reels.
- Motion: web button presses ease over 160ms on the standard curve instead of snapping. `AnimatedNumberReadout` uses the standard HIG curve (`tokens.easing.standard`) on web and native. Native digit reels mount 20 rows instead of 30, a third less to render per animated place.
- Native test consumers track Expo SDK 58.0.23, which expects `react-native-safe-area-context ~5.11.1`, and the peer range now accepts it.
- Accept `@bloxwap/chart` 0.4.0: the required peer is now `^0.3.0 || ^0.4.0`, and HIG develops, smoke-tests and documents against 0.4.0. Chart 0.4.0 only adds indicator APIs, so `PriceChart` and `chartTheme` are unchanged.
- Pin `@bloxwap/font` 0.1.4. Its web CSS now loads unicode-range subsets, so pages download only the scripts they render. The variable sources behind `@bloxwap/hig/native-fonts` and `@bloxwap/hig/og-fonts` are byte-identical to 0.1.2, so the generated TTFs and their SHA-256 hashes are unchanged; only the manifests' source version changes.
- The docs site now installs `@bloxwap/haptic` 0.3.0 and `@bloxwap/sfx` 0.2.1, inside HIG's supported peer ranges, instead of the older 0.1.0 builds.

## 0.2.0

- Publish HIG as one npm package, `@bloxwap/hig`, replacing the eight `@bloxwap/hig-*` packages. Each former package is now a subpath entry: `@bloxwap/hig-react/button` becomes `@bloxwap/hig/react/button`, `@bloxwap/hig-tokens/css` becomes `@bloxwap/hig/tokens/css`, and so on. Entry names and exports are unchanged.
- Every renderer, device and overlay peer is optional; `@bloxwap/chart` `^0.3.0` remains the one required peer (#96).
- The release dry run, verifier and publish workflow handle exactly one tarball. Font-binary, OG-font budget and chart-boundary gates now check paths inside it.
- The `@bloxwap/hig-*` 0.1 packages are deprecated on npm and point to `@bloxwap/hig`.

## 0.1.0

- Initial coordinated release of contracts, tokens, native fonts, OG fonts, feedback, React, chart and React Native packages.
- Configure a brand accent with `HIGProvider primaryColor` on web and native. Nested providers inherit it, overlays and chart crosshair labels follow it, and primary fills receive contrasting black or white labels.
- Preserve Bloxwap green by default and keep status, buy/sell, and approved brand-mark colours independent of the custom primary accent. Native Display P3 hosts convert custom sRGB accents.
- Adopt pink negative/sell and neon-yellow warning roles, with severity-based callout strokes and glows on web and native.
- Includes interface guidelines, accessibility and consumer validation, and release artifact verification.
- Registry publication remains subject to maintainer approval and the release gates in `planning/release-blockers.json`.
